# 输出文件夹与阅读页

中文 | [English](output.en.md) · [返回 README](../README.md)

## 输出文件夹

看完一个视频或录音，会得到一个输出文件夹（Media Bundle）：

```text
media/<name>/
├── source_map.json
├── source_map.md     # 生成的阅读副本，给 agent 读
├── notes.json        # 笔记
├── media.html        # 生成的阅读页，打开这个
└── assets/frames/    # 视频里有用的画面才会有
```

原始录音留在原处。转换过的音频、模型的原始输出和临时提取文件，在任务完成或报错后都会删掉。输出文件夹里保留原文底稿、笔记、生成的文件和选出的关键帧。

## 阅读页

在浏览器里打开 `media.html`，也就是阅读页（Media Page）。它是单个文件，断网也能看，不需要服务器。宽屏时笔记和全文并排，滚动时一起走；窄屏时分成两个标签页。`media.html` 和 `source_map.md` 都由脚本生成，agent 不直接写它们，所以随时可以重新生成，也不要手改。

全文（Media Reader）保持原来的顺序，分成自然段，带时间戳和说话人名字（或固定的匿名标签）。默认每段原文旁边就是译文，也可以只看一种语言。原文和目标语言相同时，不重复显示译文。听不清或有歧义的地方，会在影响理解的位置注明。两边都能搜索，也能按说话人筛选。

视频里讲解要靠画面才能看懂的地方，会保留关键帧（Visual Evidence），显示在对应的段落旁边，点开可以看大图。

## 笔记

笔记（Media Notes）每一段都链接到全文里出处的段落，那些段落也能链回笔记。笔记的结构按内容类型（Reading Type）来定：

| 内容类型 | 笔记怎么组织 |
| --- | --- |
| 对话（`dialogic`） | 问题、立场、feedback、决定、有依据的承诺 |
| 讲解（`expository`） | 概念、论证、机制、例子、限定条件 |
| 操作（`procedural`） | 目标、前提、步骤、检查、纠正、结果 |
| 报道（`reportorial`） | 背景、时间线、来源、证据、不确定之处 |
| 反思（`reflective`） | 经历、理解、矛盾、正在形成的打算 |

课程类内容会附上详细的学习指导。对话类会把不同说话人的观点分开，也把建议和承诺分开。某个待办没有说明谁负责或什么时候完成，笔记会写明没有。

<details>
<summary>原文底稿、笔记和渲染</summary>

`source_map.json` 是原文底稿，存着来源信息、完整的原文和译文段落、说话人依据、章节、局限和关键帧。全文和笔记用的是同一份底稿，所以做完全文再写笔记不用重新转写。来源和语言核对无误时，已有的底稿可以直接复用。

`notes.json` 存笔记的小标题和纯文本段落。每段可以列出它属于哪些说话人、引用了哪些 `S...` 段落、旁边显示哪些 `F...` 关键帧。详细的说话人诊断信息留在底稿里。

`write_reader_copy.py` 只需要底稿，用来在写笔记之前生成 `source_map.md`。`render_bundle.py` 要等笔记写完才运行：它校验这两个文件，再写出 `source_map.md` 和 `media.html`，缺少 `notes.json` 时直接报错。校验不通过时，它们会报告每个问题的位置，已有文件保持不变。

阅读页的标题就是底稿里的 `media.title`，也就是来源自己的标题：在线视频用平台上的标题，本地文件用你给的标题、文件元数据里的标题或文件名。标题保持原文，不翻译也不改写。

</details>

<details>
<summary>旧版输出文件夹</summary>

旧版输出文件夹不会自动转换。它的 `source_map.json` 校验会失败，因为说话人的 `role` 和 `identity_basis` 字段以及顶层的 `glossary` 已经去掉了。你同意后，agent 会删掉这些字段并重新渲染，不重新转写。旧的 `notes.json` 里如果有 `title` 字段，agent 会删掉它，因为标题现在取自底稿。

已有的 `media.md`、`media-card.md`、`reader.html` 和旧的 `card.json` 都留在原处，agent 不读、不转换、也不删除。想在新页面上看到笔记，让 agent 重新写一份。

</details>
